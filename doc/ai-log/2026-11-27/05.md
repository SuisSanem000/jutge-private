## Summary

Fixed the zsh terminal errors when copy-pasting the CLI quickstart commands and improved the error message when `OPENROUTER_API_KEY` is unset or still uses a placeholder.

## Root Causes & Fixes

1. **Zsh `#` comments & backticks in copy-pasted commands ([public/index.html](file:///Users/siminshoeibizadeh/mienne/Programming/dev/projects/scholarship-project-uni/jutge-private/projects/02-pedit-cli-and-viewer/problem-editor/pedit/public/index.html) & [pedit/README.md](file:///Users/siminshoeibizadeh/mienne/Programming/dev/projects/scholarship-project-uni/jutge-private/projects/02-pedit-cli-and-viewer/problem-editor/pedit/README.md)):**
   - Interactive `zsh` does not ignore `#` comments by default and executes backticks (e.g., `` `pedit ...` `` inside `bun link # optional: enables \`pedit ...\` globally`).
   - Removed all `#` comments and backticks from terminal code blocks, used `cd ~/Downloads/pedit && bun install` so it works from any folder, and put non-AI commands (`--help`, `list`, `viewer`) first.
2. **Placeholder `OPENROUTER_API_KEY` ([src/ai.ts](file:///Users/siminshoeibizadeh/mienne/Programming/dev/projects/scholarship-project-uni/jutge-private/projects/02-pedit-cli-and-viewer/problem-editor/pedit/src/ai.ts)):**
   - Added a check for placeholder keys (`your-key`) so AI commands print a clear message explaining how to set a real key and noting that non-AI commands (`list`, `status`, `show`, `build`, `pdf`, `lint`, `viewer`) work without a key.
