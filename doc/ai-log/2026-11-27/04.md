## Summary

Added automatic client-side PDF compilation in [public/index.html](file:///Users/siminshoeibizadeh/mienne/Programming/dev/projects/scholarship-project-uni/jutge-private/projects/02-pedit-cli-and-viewer/problem-editor/pedit/public/index.html) so when a user opens a `.pbm` folder (such as `lol-eda.pbm`) on GitHub Pages that has `problem.<lang>.tex` + samples without a prebuilt `.pdf`, the viewer compiles a full A4 PDF right in the browser (with a loading indicator, zero server upload) and displays it in the PDF iframe and **Open PDF** button.

## How It Works

- When `state.tab === 'pdf'` and `p.localFiles` has `problem.<lang>.tex` without a prebuilt `p.pdfs[lang]`, `compileLocalPdf()` shows `"Compiling PDF statement (<LANG>)..."` and lazily loads **KaTeX** + **html2pdf.js** from CDN.
- `buildClientStatementHtml()` parses `\Problem{...}`, `\Statement`, `\Input`, `\Output`, `\Observation`, `\Precondition`, `\Author` (with `en`/`ca`/`es` headings), renders `$...$` / `$$...$$` math via KaTeX, and formats `sample-*.inp` / `sample-*.cor` pairs.
- `html2pdf` renders the statement to a `blob:` PDF URL, caches it in `p.pdfs[lang]`, displays `<iframe src="${blobUrl}">`, and enables **Open PDF**.
