## What Works & Is Practical

1. **Deterministic CLI (`list`, `status`, `show`, `build`, `pdf`, `lint`, `verify`, `clean`, `meta`, `handler`):**
   - Fast, scriptable (`--json`), and wraps unmodified `jtk` (`4.4.50`).
   - `meta` and `handler` let authors fix titles/authors/compilers deterministically without spending LLM tokens.
2. **Closed-loop AI authoring (`create`, `edit`, `chat`):**
   - Grounds generation in hidden `spec/` & `skills/` and verifies with `jtk make` + `jtk lint` automatically.
   - Enforces `*.cor` and `problem.yml` write guards so the LLM cannot fake expected outputs or leak credentials.
3. **Local Web PDF Viewer (`pedit viewer --dir ...`):**
   - Practical for reviewing a whole folder of `.pbm` problems side-by-side (PDF + LaTeX + Solution + Samples + Handler/Meta) with one-click **Rebuild PDF**, **`jtk make`**, and **`jtk lint`**, plus headless Chrome PDF fallback when `pdflatex` is unavailable.
4. **Static GitHub Pages Demo (`pedit-demo`):**
   - Good for zero-install live demos and browser-only inspection of prebuilt `.pbm` folders via **Open `.pbm` from PC** or drag-and-drop (no server upload).

## Practicality Gaps Found

1. **Multi-language `.pbm` subfolders skipped in browser picker (`public/index.html`):**
   - `ingestPbmEntries` skips any path with `inner.includes('/')`, so `.pbm` problems that store `en/problem.en.pdf` or `en/problem.en.tex` in language subdirectories won't show their PDFs/TeX in the browser viewer (even though `src/pdf.ts` supports them).
2. **`Rebuild PDF` tab behavior (`public/index.html`):**
   - Clicking **Rebuild PDF** while viewing `LaTeX` or `Solution` runs `/action` and switches to `Logs` instead of switching to `PDF Statement` and refreshing the PDF iframe.
3. **`pedit show` path check (`src/index.ts`):**
   - `show` only checks `file === "problem.yml"` rather than using the full `assertSafeRelativePath` guard (e.g., `en/problem.yml` or `../` isn't blocked).
4. **Downloading `pedit.tar.gz` via browser:**
   - Safari/Chrome often auto-extracts `.tar.gz` into `~/Downloads/pedit/` and requires `bun install` before `bun run src/index.ts ...`. Using `bun link` (or cloning the repo) is much smoother for repeat CLI use.

## Recommended Next Improvements

- Fix the 3 small code gaps above (`en/` subfolder support in `ingestPbmEntries`, `Rebuild PDF` switching to the `PDF Statement` tab, and `assertSafeRelativePath` in `pedit show`).
- Add a global `bun link` instruction in the quickstart so `pedit ...` works from any directory without `bun run src/index.ts`.
