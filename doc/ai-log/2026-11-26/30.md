## Why the Download Button Gives Source Code (`pedit.tar.gz`)

- `pedit` is a **Bun + TypeScript** project (`src/index.ts`), not a precompiled binary yet.
- GitHub Pages is static hosting, so it currently packages the `pedit/` folder into `pedit.tar.gz` for you to unpack and run locally with `bun`.

## How to Run `pedit` as a Real CLI Locally

```bash
cd projects/02/problem-editor/pedit
bun install
bun link          # registers `pedit` globally on your machine
pedit --help
pedit viewer --dir ..
```

- Notice `jtk` itself works the exact same way (`@jutge.org/toolkit` is a Bun/TS package installed via `bun`!).

## Option: Compiled Standalone CLI Binary on Pages

- If you want the GitHub Pages download button to give a **ready-to-run binary** (no `bun install` needed), we can run `bun build --compile` inside GitHub Actions to publish `pedit-macos-arm64` and `pedit-linux-x64` executables alongside `pedit.tar.gz`. Tell me if you want me to add that.
