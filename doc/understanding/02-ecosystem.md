# 02 — Ecosystem

All repos are under `resources/jutge_repos/` (cloned, read only). Data from git history and READMEs.

## Layers

1. **Frontends:** jutge-web-new (Next.js student site), jutge-web-prof (instructor app), jutge-vscode (extension), jutge-cli (`jutge` command).
2. **API:** `api.jutge.org`. Clients are generated by jutge-api-clients from `https://api.jutge.org/api/dir`. Docs: jutge-api-doc.
3. **Authoring:** **jutge-toolkit (`jtk`)** (Simin's focus). Predecessor: jutge-toolkit-legacy (Python).
4. **Grading:** queue → worker over SSH → Docker image `jutge-all` → `jutge-submit` → `jutge-start` → driver (`jutge-driver-std`, `-graphic`, `-circuits`).

## Legacy → jtk command mapping

| Legacy | jtk |
|---|---|
| `jutge-make-problem` | `jtk make`, `jtk verify`, `jtk clean` |
| `jutge-make-quiz` | `jtk quiz` |
| `jutge-compilers` | `jtk compilers` (developer mode only) |
| `jutge-code-metrics` | `jtk metrics` |
| (none) | `generate`, `ask`, `lint`, `upload`, `download`, `clone`, `share`, `remove`, `stage`, `submit`, `convert`, `doctor`, `config`, `upgrade` |

The legacy toolkit had no AI and no API upload (upload was through the website).

## What matters for the rewrite

- The `.pbm` format is shared by jtk, legacy and the three drivers. A rewrite must stay compatible with what the drivers read (see file 04).
- jtk talks to the server only through the Jutge API (problems and AI). The Python client in jutge-api-clients is out of date compared to what jtk calls.
