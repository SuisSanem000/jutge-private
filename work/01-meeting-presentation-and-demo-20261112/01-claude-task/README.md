## The Generated Problem Anatomy (`dominant-peaks.pbm/`)

Inside [**`dominant-peaks.pbm/`**](./dominant-peaks.pbm/):

- `handler.yml`: Configured for compiler mode `G++17` with `source_modifier: none` and 1.0s limit.
- `problem.en.yml`: Metadata (Title: "Dominant Mountain Peaks", Author: Simin Shoeibi).
- `problem.en.tex`: Formal LaTeX problem statement with formal Description, Input, Output, and `\SampleTwoCol` table.
- `solution.cc`: Optimal $O(N)$ C++17 golden solution (right-to-left scan tracking running maximum) strictly adhering to the Pedagogical Constitution.
- `solution-slow.cc`: Naive $O(N^2)$ solution for limits verification.
- `sample-1.inp` & `sample-1.cor`: Public sample 1 (standard sequence).
- `sample-2.inp` & `sample-2.cor`: Public sample 2 (strictly descending sequence).
- `generate.ts`: Executable TypeScript/Bun test generator producing edge correctness tests and large efficiency tests ($N = 100,000$).
- `private-*.inp` & `private-*.cor`: Private test cases generated by `generate.ts` and `.cor` outputs compiled via `jtk make`.
- `scores.yml`: Integer point distribution summing to 10 (4 points for correctness, 6 points for efficiency).
- `.clang-format`: Formatting configuration.

## How to Verify or Reproduce

To re-run and verify the problem locally:

```bash
cd work/01-meeting-presentation-and-demo-20261112/01-claude-task/dominant-peaks.pbm

# 1. Run the test generator to produce private tests
./generate.ts

# 2. Compile solution.cc and generate all .cor expected outputs
jtk make exe cor

# 3. Lint the directory (passes with 0 errors)
jtk lint

# 4. Verify that the slow solution triggers time-limit exceeded
jtk verify solution-slow.cc
```
