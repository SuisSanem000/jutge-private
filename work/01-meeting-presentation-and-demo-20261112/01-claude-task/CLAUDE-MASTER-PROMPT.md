================================================================================
PROBLEM DESIGN & ALGORITHM SPECIFICATION

Title: Dominant Mountain Peaks
Author: Simin Shoeibi
Email: simin.shoeibi@estudiantat.upc.edu
Language: en

Description:
Given a sequence of integers representing the elevations of mountain peaks from left to right, a peak is "dominant" if it is strictly higher than every peak that appears to its right. The last peak is always dominant by definition. For each case, print the dominant peaks in their original left-to-right order, on one line, separated by single spaces.

Constraints:
- Input contains multiple test cases until EOF.
- Each case starts with an integer N (1 <= N <= 100,000), followed by N integer elevations.
- Elevations: -10^9 <= E_i <= 10^9.
- Time limit: 1.0 second. Memory limit: 128 MB.

Complexity Requirements:
- Optimal (solution.cc): O(N) time, O(N) auxiliary space. Scan right to left keeping the running maximum, collect dominant peaks, print them in reverse so they appear left to right.
- Slow alternative (solution-slow.cc): naive O(N^2). For each peak, scan the peaks to its right with a `break`-style early exit (stop at the first peak that is >= the current one). Its worst case is a strictly DECREASING sequence (every peak is dominant, so every scan is full). It must pass all correctness tests but exceed the time limit on the efficiency tests. Do NOT write the inner loop as a branch-free count over all elements: the compiler vectorizes it and the slowdown falls under the required 5x.
