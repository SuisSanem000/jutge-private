## Slide 3: What I Learned (The Rules for Making Problems)

### On the Slide:
- **Early Exit:** Loops must stop as soon as they find the answer.
- **Clean C++17:** Standard vectors, strings, and queues only.
- **No Unordered Maps:** Forbidden to prevent unpredictable speed and order.
- **Integer Scores:** Points in `scores.yml` must sum to exactly 10.
- **Output Rule:** Expected outputs (`.cor`) must be compiled from code, never written by hand.
- **Folder Structure (`.pbm`):** Contains `handler.yml`, `problem.en.tex`, `solution.cc`, and tests.

## Slide 5: The Problem: "Dominant Mountain Peaks"

### On the Slide:
- **The Story:** A mountain peak is dominant if it is higher than all peaks to its right.
- **Input:** A list of mountain peak heights (up to 100,000 numbers).
- **Output:** Print only the dominant peaks in their original order.
- **Simple Examples:**
  - Input: `1 4 2 3 5` $\rightarrow$ Output: `5`
  - Input: `3 1 4 1 2 1` $\rightarrow$ Output: `4 2 1`
  - Input: `9 7 4 -2` $\rightarrow$ Output: `9 7 4 -2`
- **Fast Solution (`solution.cc`):** Scans right-to-left in linear time: $O(n)$.
- **Slow Solution (`solution-slow.cc`):** Naive search in quadratic time: $O(n^2)$.

### What to Say Aloud:
> *"Here is the problem we created: Dominant Mountain Peaks. A peak is dominant if it is higher than all peaks to its right. The fast solution scans from right to left in linear time. The slow solution does a naive search in quadratic time."*

## Slide 9: What is "Headless Core"? (Phase 3 Idea)

### On the Slide:
- **Current Issue:** Current `jtk` has terminal colors and questions mixed with the code.
- **What Headless Means:** Headless simply means: the engine does all the work without any user interface.
- **The Solution:** Put the engine (compiling, testing, uploading) in a clean library called `@jutge/core`.
- **One Engine Powers Everything:**
  1. The **Terminal CLI** (`jtk v5`) for humans.
  2. The **Web SaaS App** for browser problem editing.
  3. **AI Agents (Claude Code)** via clean JSON data.

### What to Say Aloud:
> *"For Phase 3, my suggestion is to separate jtk into a headless engine called `@jutge/core`. 'Headless' just means no terminal colors or questions. That way, the terminal CLI, the web app, and AI agents can all use the exact same engine."*
