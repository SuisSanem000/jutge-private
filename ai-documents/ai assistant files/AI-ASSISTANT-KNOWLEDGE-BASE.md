## 2. Inviolable Architectural Rules

1. **Deterministic Outputs (`*.cor`):**  
   NEVER write or prompt an LLM to generate `*.cor` files. They are ALWAYS generated by running the golden solution (`solution.cc` / `solution.py`) against input files (`*.inp`) via `jtk make`.
2. **Problem Packaging (`.pbm`):**  
   Every problem is encapsulated in a directory ending with `.pbm` (e.g. `my-problem.pbm`).
3. **Execution Driver Isolation:**  
   Do not modify `jutge-driver-std` or `jutge-dockerfiles` without explicit request. They run in production for live university grading across UPC.
4. **Primary Runtime:**  
   `jutge-toolkit` is built with **Bun** and **TypeScript**. Commands are invoked with `jtk` or `bun run dev` inside `jutge_repos/jutge-toolkit`.

## 4. Key CLI Commands Reference (`jtk`)

| Task | Terminal Command |
|---|---|
| Check dependencies | `jtk doctor` |
| View config & credentials | `jtk config show` |
| Clone a problem template | `jtk clone [template] -d <name>.pbm` |
| AI generate problem | `jtk generate problem -k io -d <name>.pbm` |
| Build binaries, `.cor`, statements | `jtk make` (inside `.pbm` directory) |
| Verify candidate solution | `jtk verify <candidate_file>` |
| Validate problem structure | `jtk lint` |
| Clean build artifacts | `jtk clean` |
| Publish to Jutge.org | `jtk upload` |
| Submit solution to live judge | `jtk submit -l <lang> <solution_file>` |
