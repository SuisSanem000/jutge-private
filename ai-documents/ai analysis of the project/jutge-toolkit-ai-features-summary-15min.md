## 1. The 60-Second Pitch

* **What is `jutge-toolkit` (`jtk`)?**  
  A modern **TypeScript / Bun** command-line toolkit used by Jutge instructors to create, compile, verify, and upload programming problems to [Jutge.org](https://jutge.org).
* **What is `jtk generate problem`?**  
  An AI-powered generator that transforms a simple text description into a **complete Jutge problem package** (LaTeX statement, golden solution, test cases, translations, generator scripts, and eco/cost audit).
* **Tech Stack:** Bun, TypeScript, Commander.js, Inquirer (TUI), Zod (schema validation), Handlebars (prompts), Jutge API v2 (SSE streaming).

---

## 2. Anatomy of a Problem (`.pbm` folder)

When a problem is created, it lives in a `<problem_name>.pbm` directory:

| File | Purpose |
|---|---|
| `problem.<lang>.tex` | LaTeX statement using Jutge contest macros (`\Problem{}`, `\Statement`, `\Input`, `\Output`, `\Sample`). |
| `problem.<lang>.yml` | Problem metadata (title, author, email, AI model). |
| `solution.<ext>` | **Golden reference solution** (e.g. `solution.cc`, `solution.py`). |
| `sample-*.inp` | **Public sample test inputs** (shown to students in problem statement). |
| `test-*.inp` | **Private test inputs** (used to grade correctness and edge cases). |
| `generate-*.py` | Python scripts to generate `random`, `hard`, and `efficiency` test inputs. |
| `handler.yml` | Evaluation mode (`std` for standard I/O, `quiz`, or `game`). |
| `README.md` | Generation audit trail: tokens used, cost in €, CO₂ grams, water, and Wh. |

> ⚠️ **Golden Rule of Jutge:**  
> Output files (`*.cor`) are **never written by hand or generated by the LLM**. They are created deterministically by running the golden solution against `.inp` files during `jtk make`.

---

## 3. How `jtk generate problem` Works

Syntax:
```bash
jtk generate problem -k io -d my-problem.pbm
```

### Two Problem Kinds (`-k, --kind`)
1. **`io` (Standard I/O - default):** Complete program reading from `stdin` and writing to `stdout`.
   - Supported languages: C, C++, Python, Haskell, Java, Rust, R, Clojure.
2. **`funcs` (Function problems):** Students implement specific functions/classes called by a provided driver.
   - Supported languages: Python, Haskell, Clojure (via `RunPython`, `RunHaskell`, `RunClojure`).
   - Automatically generates individual test cases per function, Python doctests (`sample.dt`), and `scores.yml` for partial points.

## 4. The 6-Step Generation Pipeline (`lib/create-io.ts`)

```
[1. Specification] ──> [2. Statement (LaTeX)] ──> [3. Testcases (.inp)]
                                                          │
[6. Eco Audit (README)] <── [5. Generators (.py)] <── [4. Solutions & Translations]
```

1. **Specification:** Ingests title, description, languages, and settings (interactively or via `--input spec.yml`).
2. **Statement Generation:** Prompts LLM using `assets/prompts/io/creators/create-statement.tpl.txt` and contest LaTeX examples.
3. **Testcase Generation:** Generates `sample-1.inp`, `sample-2.inp`, `test-1.inp`, `test-2.inp`.
   * *Clever mechanism:* Uses `bot.forgetLastInteraction()` between calls so the LLM doesn't repeat identical test cases.
4. **Solutions & Translations:**
   * Synthesizes the golden solution and alternative solutions using language style rules (`assets/prompts/io/proglangs/`).
   * Translates LaTeX statements into Catalan (`ca`), Spanish (`es`), etc., keeping formulas and variable names intact.
5. **Generators:** Generates Python scripts (`generate-random.py`, `generate-hard.py`, `generate-efficiency.py`) matching the Jutge CLI signature (`sys.argv[1]` = cases, `sys.argv[2]` = seed).
6. **Audit & Sustainability:** Calculates token count, financial cost (€ + 21% VAT), water liters, Wh, and CO₂ emissions in `README.md`.

## 6. How It Fits Into the Jutge Workflow

Generating a problem is only Step 1:
```text
1. jtk generate problem  ──> AI drafts problem folder (.pbm)
2. Edit / Review         ──> Instructor inspects and polishes statement/code
3. jtk make              ──> Compiles golden solution, generates .cor, builds PDFs
4. jtk verify            ──> Tests candidate/alternative solutions locally
5. jtk lint              ──> Validates directory structure & metadata
6. jtk upload            ──> Pushes finished problem to Jutge.org
```

## 7. High-Impact Talking Points for Your Professor

Bring these up in your conversation to show you didn't just look at the README, but studied the code and thought critically about improvements:

### 1. "Current generation is open-loop (No self-correction)"
* **The issue:** `jtk generate problem` creates files on disk, but never compiles or tests them during generation. If the LLM produces code with a typo, or test inputs that violate constraints, the instructor only finds out later during `jtk make`.
* **Your proposal:** Implement a **closed-loop generation loop**:
  * Generate solution + inputs ➡️ automatically compile and run ➡️ if error, feed traceback back into the LLM to self-correct before saving.

### 2. "Test case generators are untested at generation time"
* **The issue:** The generated `generate-random.py` or `generate-hard.py` scripts are often written but never executed.
* **Your proposal:** Run `python3 generate-<type>.py 5 42` directly during problem creation to verify zero-exit codes and validate generated format.

### 3. "Expand function problem (`funcs`) support to C++ and Java"
* **The issue:** Currently `funcs` only supports Python, Haskell, and Clojure.
* **Your proposal:** Add harness templates for C++ (`RunCC`) and Java so instructors teaching introductory algorithms in C++ can use `jtk generate problem -k funcs`.
