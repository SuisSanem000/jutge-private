## 1. Executive Summary & Project Background

**Jutge.org** is an open educational automated judge platform developed and maintained at the **Universitat Politècnica de Catalunya (UPC - BarcelonaTech)**. It is the primary platform used across UPC computer science and informatics degrees (FIB - Facultat d'Informàtica de Barcelona) for:
- Hands-on laboratory programming assignments
- Automated code evaluation and instant grading (Accepted, Wrong Answer, Time Limit Exceeded, etc.)
- Formal university exams and continuous evaluation
- Competitive programming contests (including the Catalan Olympiad in Informatics, OIcat)

### The Current Modernization Wave
The platform is undergoing an active architectural transition:
- **Decoupled API-First Architecture:** Transitioning from monolithic server scripts to **Jutge API v2 (`api.jutge.org`)**.
- **Modern Frontends:** Rebuilding client web applications using Next.js 16, React 19, and Tailwind CSS (`jutge-web-new` for students at `new.jutge.org` and `jutge-web-prof` for professors).
- **Modern Tooling Runtime:** Shifting developer and authoring tools to **Bun and TypeScript** (`jutge-toolkit`, `jutge-cli`).
- **Pedagogical AI (`JutgeAI`):** Integrating LLM capabilities for automated problem authoring, edge-case generation, multilingual statement translation, and smart educational assistance.

## 2. Scholarship Strategy: "Show More, Do Less"

As a Master's scholarship student working across this open-source ecosystem, your goal is to deliver **high-impact, highly visible improvements** while minimizing frictional bottlenecks.

### Where to Avoid (Initially): Low-Level Execution Sandbox
- **Repositories:** `jutge-driver-std`, `jutge-driver-circuits`, `jutge-dockerfiles`, `jutge-exec`.
- **Why Avoid:** 
  1. These repositories manage kernel-level Linux sandboxing (`cgroups`, `chroot`, Linux syscall filtering, process isolation under `nobody`).
  2. Local testing requires complex Docker setups and root permissions.
  3. They have a **critical blast radius**: a regression in a judge driver can break live university exams across UPC.

### The Strategic "Sweet Spot" (High Visibility / Low Friction):
1. **`jutge-toolkit` (`jtk`) — Problem Authoring & AI Generation:**
   - Written in modern **TypeScript / Bun**.
   - Directly used by professors (Jordi Petit, Salvador Roura, Jordi Cortadella) who design exam and contest problems.
   - Any enhancement in problem generation quality, error recovery, or testcase verification produces immediate, tangible value for your professors.
2. **`jutge-vscode` & `jutge-cli` — Student & Instructor Clients:**
   - Immediate visual feedback loop (pressing `F5` runs the extension host in VS Code).
   - Direct impact on thousands of students submitting code in labs.

## 3. Fundamental Concepts of Jutge.org

### The Golden Rule of Evaluation
> **Crucial Rule:** In Jutge.org, expected output files (`*.cor`) are **never written by hand and never generated by an LLM**.
> Output files are deterministically produced by compiling the **golden reference solution** (`solution.cc`, `solution.py`, etc.) and executing it against the test inputs (`*.inp`) during `jtk make`.

### Anatomy of a Problem Directory (`.pbm`)
A Jutge problem is self-contained in a folder ending in `.pbm`:

```text
my-problem.pbm/
├── problem.en.tex       # LaTeX problem statement (English, original)
├── problem.en.yml       # Metadata (title, author, email, AI model)
├── problem.ca.tex       # Translated statement (Catalan)
├── problem.es.tex       # Translated statement (Spanish)
├── handler.yml          # Problem handler type ('std', 'game', 'quiz')
├── solution.cc          # Golden reference solution (C++)
├── solution.py          # Alternative candidate solution (Python)
├── sample-1.inp         # Public sample input (visible in problem statement)
├── sample-2.inp         # Public sample input 2
├── test-1.inp           # Hidden evaluation testcase 1
├── test-2.inp           # Hidden evaluation testcase 2 (corner/edge cases)
├── generate-random.py   # Script to generate randomized test inputs
├── generate-hard.py     # Script to generate extreme boundary inputs
├── generate-efficiency.py # Script to generate maximum-size inputs
├── README.md            # LLM generation audit log & carbon/cost report
└── .gitignore           # Ignores build artifacts (.cor, .pdf, .out)
```

### Problem Categories
1. **Standard I/O (`io`):** Program reads from `stdin` and writes to `stdout`.
2. **Functions (`funcs`):** Students implement specific functions or classes; evaluation harness wraps them with a driver `main` file.
3. **Graphical (`graphic`):** Program outputs a PNG image (`output.png`), evaluated using `pil-turtle` against a reference image.
4. **Circuits (`circuits`):** Digital design problems written in Verilog, formally verified using EDA tools.
5. **Quizzes (`quiz`):** Multiple-choice, fill-in-the-blank, or ordering questions evaluated declaratively.
